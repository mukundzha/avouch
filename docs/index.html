I was paying for a reviewer that spent half its report on code I never wrote.

It queued my real diffs behind everyone else's and charged per page. I wanted a reviewer that looks only at what I'm about to push, runs locally in the seconds before git push, and costs nothing. So I built one.

[ HOW IT WORKS ]

How avouch reviews every diff

  1. 01

    Asks git what you changed

    One commit's worth of files: staged, unstaged, or a whole directory via --not-git. The diff is the scope.

  2. 02

    Walks the AST

    The stdlib ast module parses each changed .py. 17 rules, no dependencies, no network, nothing sent anywhere.

  3. 03

    Reports only your diff

    Findings render with file:line and carets. Exit codes gate CI: 0 clean, 1 findings, 2 error.

Built to get out of the way

First run, clean

avouch init measures your real code — parameters, nesting, complexity — and writes an avouch.toml your repository already passes. The first report says nothing.

$ avouch init
measured 12 maxima across 34 files
wrote avouch.toml

$ avouch
All clean. — 0 findings

Actually local

No daemon, no cloud. Python 3.10+ and git — that's the whole install.

Future findings only

Baseline snapshots make later runs show nothing but what changed since the snapshot.

CI-native

Questions

Does it send my code anywhere?

No. avouch has no network code at all — parsing is standard-library, and nothing leaves the machine.

Will my legacy code light up the report?

Only the files your next commit touches run. avouch init sets limits your repo already passes, and baseline snapshots keep later reports to what changed.

Can I run it in CI?

Yes. --json gives a versioned document and exit codes gate the pipeline: 0 clean, 1 findings, 2 error.

Is it an AI reviewer?

No. It's a deterministic rule engine over the AST — the same findings for the same code, forever, free.

avouch is the zero-dependency review layer. Get back to shipping.
